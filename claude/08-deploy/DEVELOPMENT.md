# Deploy to local minikube: development notes

## Layout (`deploy/`)
- `k8s/`: plain manifests, one file per service, plus `namespace.yaml`, `configmap.yaml` and `wait-for-migrate-rbac.yaml`. Everything is in the namespace `cleanair`.
- `jobs/fetcher-backfill.yaml`: the backfill Job template. It is not in `k8s/`, so `kubectl apply -f deploy/k8s/` does not start a backfill.
- `local-deploy.sh`: builds, loads images, creates config and secrets, and applies the manifests. It can be run again to update.
- `run-backfill.sh START END`: creates one backfill Job (`DD-MM-YYYY`, inclusive).

Both scripts use `kubectl` if it is installed, otherwise `minikube kubectl --`.

## Usage
```bash
./deploy/local-deploy.sh
kubectl port-forward -n cleanair svc/api 8080:8080
kubectl create job -n cleanair --from=cronjob/fetcher fetcher-manual
./deploy/run-backfill.sh 26-10-2026 28-10-2026
kubectl delete -f deploy/k8s/
```

## Workloads
| Service | Workload | Image | Storage |
|---|---|---|---|
| `api` | Deployment + Service :8080 | `cleanair-api:local` | |
| `fetcher` | CronJob `0 23 * * *` | `cleanair-fetcher:local` | |
| `fetcher-backfill` | Job, on demand | `cleanair-fetcher:local` | |
| `archiver` | CronJob `0 23 * * *` | `cleanair-archiver:local` | |
| `migrate` | Job | `flyway/flyway:11.10.0` | |
| `mysql` | StatefulSet + headless Service | `mysql:8.4.5` | PVC 1Gi |
| `fileserver` | StatefulSet (1) + Service :5000 | `sigoden/dufs:v0.47.0` | PVC 1Gi |
| `pushgateway` | Deployment (1) + Service :9091 | `prom/pushgateway:v1.11.1` | |
| `prometheus` | StatefulSet + Service :9090 | `prom/prometheus:v3.5.0` | PVC 1Gi |
| `grafana` | Deployment (1) + Service :3000 | `grafana/grafana:12.1.0` | none (provisioned from config) |

`dummy-dev-populator` is not deployed.

**Schedules are in UTC.** A CronJob without `spec.timeZone` runs on the controller's clock, which is UTC in minikube. So `0 23 * * *` is 23:00 UTC (01:00 Sofia time in summer). Add `timeZone: Europe/Sofia` to the CronJobs if local time is wanted.

## Configuration
| Source | Kubernetes object | Keys |
|---|---|---|
| `deploy/k8s/configmap.yaml` | ConfigMap `cleanair-config` | `DB_HOST`, `DB_PORT`, `PUSHGATEWAY_URL`, `ARCHIVE_URL`, `PORT` |
| `.env` (generated by the script) | ConfigMap `cleanair-db` | `DB_NAME`, `DB_USER`, `ARCHIVE_USER` |
| `.env` (generated by the script) | Secret `cleanair-secrets` | `OPENAQ_API_KEY`, `MYSQL_ROOT_PASSWORD`, `MYSQL_PASSWORD`, `ARCHIVE_PASSWORD`, `GRAFANA_ADMIN_PASSWORD` |
| `mysql/migrations/` | ConfigMap `mysql-migrations` | `V*.sql` mounted at `/flyway/sql` |
| `prometheus/prometheus.yml` | ConfigMap `prometheus-config` | mounted at `/etc/prometheus` |
| `grafana/provisioning/{datasources,dashboards}` | ConfigMaps `grafana-datasources`, `grafana-dashboards` | mounted under `/etc/grafana/provisioning` |

- **Env names:** the apps get the same env names as in `docker-compose.yml`. `DB_PASSWORD` comes from `MYSQL_PASSWORD` in the secret.
- **Defaults** when the key is missing or empty in `.env`:
  - `ARCHIVE_USER` and `ARCHIVE_PASSWORD` default to `archiver`, and `GRAFANA_ADMIN_PASSWORD` to `admin` (the compose defaults).
  - `MYSQL_ROOT_PASSWORD` defaults to `root`, with a warning. The local `.env` has it empty, which MySQL refuses on a fresh volume. Compose did not hit this because its volume was already set up.
- **No secrets in git.** Secrets are never written to a file; the script pipes `kubectl create ... --dry-run=client -o yaml` into `kubectl apply`.

## Startup order
- **migrate waits for MySQL** through `FLYWAY_CONNECT_RETRIES=30` and the Job's `backoffLimit: 5`.
- **The apps wait for migrate.** `api`, `fetcher`, `archiver` and the backfill each have an initContainer, `registry.k8s.io/kubectl:v1.35.1 wait --for=condition=complete job/migrate`. It runs with the ServiceAccount `wait-for-migrate`, which can only read Jobs in `cleanair`.
- **Migrations run on every deploy.** `local-deploy.sh` deletes the completed `migrate` Job before `apply`, so a new `V*.sql` file is applied. Flyway skips migrations it has already applied.

## Images
- **Build and load:** `docker build -t cleanair-<app>:local <app>/` in the current Docker context (`desktop-linux` here, the same daemon minikube runs on), then `minikube image load --overwrite=true`.
- **Pull policy:** `imagePullPolicy: IfNotPresent` with the `:local` tag, so Kubernetes never tries a registry.
- **Picking up new images:** on a redeploy the script runs `rollout restart` on `api`, `grafana` and `prometheus`. On the first deploy it skips this, to avoid two pods each. CronJob runs always start new pods with the loaded image.
