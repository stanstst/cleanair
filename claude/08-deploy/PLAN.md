# Step 08: deploy to a local minikube with plain kubectl manifests

## Context
`claude/08-deploy/REQUIREMENTS.md` asks for Kubernetes manifests for every production service. Each service gets the workload type from the README "Production Deployment Guidelines" table, and everything must be deployable to a local minikube with `kubectl`.

The user made these choices:
- **No Helm.** There is one environment (local minikube), so plain YAML applied with `kubectl apply` is simpler.
- **`fetcher` and `archiver` CronJobs run every day at 23:00** (`0 23 * * *`).
- **Images are built locally** and loaded with `minikube image load`, with no registry.

Rules carried over from earlier steps: no commits, no code comments, `fetcher/`, `archiver/` and `api/` code unchanged, earlier `claude/0*` folders unchanged.

## Changes

### `deploy/k8s/` (new): one file per service
| File | Contents |
|---|---|
| `namespace.yaml` | Namespace `cleanair` |
| `configmap.yaml` | `cleanair-config`: `DB_HOST`, `DB_PORT`, `PUSHGATEWAY_URL`, `ARCHIVE_URL`, `PORT` (the same names as in `docker-compose.yml`) |
| `wait-for-migrate-rbac.yaml` | ServiceAccount, Role and RoleBinding that can `get/list/watch` Jobs, for the wait-for-migrate initContainers |
| `mysql.yaml` | Headless Service + StatefulSet, `mysql:8.4.5`, 1Gi PVC, `mysqladmin ping` readiness probe |
| `migrate.yaml` | Job `migrate`, `flyway/flyway:11.10.0 migrate`, migrations mounted from ConfigMap `mysql-migrations` |
| `fileserver.yaml` | Service + StatefulSet (1 replica), `sigoden/dufs:v0.47.0`, 1Gi PVC, credentials from the config and secret |
| `pushgateway.yaml` | Service + Deployment (1 replica), `prom/pushgateway:v1.11.1` |
| `prometheus.yaml` | Service + StatefulSet, `prom/prometheus:v3.5.0`, 1Gi PVC, config from ConfigMap `prometheus-config` |
| `grafana.yaml` | Service + Deployment (1 replica), `grafana/grafana:12.1.0`, provisioning from ConfigMaps `grafana-datasources` and `grafana-dashboards` |
| `api.yaml` | Service + Deployment, `cleanair-api:local`, port 8080, readiness on `/` |
| `fetcher.yaml` | CronJob `0 23 * * *`, `cleanair-fetcher:local`, `node src/job.js` |
| `archiver.yaml` | CronJob `0 23 * * *`, `cleanair-archiver:local`, `node src/job.js` (default `--months` 36) |

- **Shared rules:** the app images use `imagePullPolicy: IfNotPresent`; requests and limits are small; CronJobs use `concurrencyPolicy: Forbid` and `backoffLimit: 1`.
- **Waiting for migrations:** `api`, `fetcher`, `archiver` and the backfill have an initContainer `registry.k8s.io/kubectl:v1.35.1 wait --for=condition=complete job/migrate`. They only start once the schema is migrated. This replaces compose's `depends_on: migrate (service_completed_successfully)`.
- **Hostnames:** service names match the compose hostnames (`mysql`, `pushgateway`, `fileserver`, `prometheus`). So `prometheus/prometheus.yml` and the Grafana datasource work unchanged.

### Generated by the script (not committed as YAML)
- **ConfigMap `cleanair-db`:** `DB_NAME`, `DB_USER` and `ARCHIVE_USER` from `.env`. This keeps `.env` the single source for names that MySQL and the apps must agree on.
- **Secret `cleanair-secrets`:** `OPENAQ_API_KEY`, `MYSQL_ROOT_PASSWORD`, `MYSQL_PASSWORD`, `ARCHIVE_PASSWORD` and `GRAFANA_ADMIN_PASSWORD` from `.env`. The archive and Grafana passwords default to the compose defaults (`archiver`, `admin`).
- **File ConfigMaps:** `mysql-migrations`, `prometheus-config`, `grafana-datasources` and `grafana-dashboards`, built from the existing repo files, so nothing is copied.

### `deploy/local-deploy.sh` (new)
1. Starts minikube if it is not running.
2. Reads `.env`.
3. Runs `docker build` and `minikube image load` for the 3 app images.
4. Applies the namespace, then the generated ConfigMaps and Secret.
5. Deletes the old `migrate` Job, so new migrations run on every deploy, then runs `kubectl apply -f deploy/k8s/`.
6. On a redeploy, restarts `api`, `grafana` and `prometheus` so they pick up new images and config.
7. Waits for `migrate` and every rollout, then prints the pods.

### `deploy/jobs/fetcher-backfill.yaml` + `deploy/run-backfill.sh` (new)
- A Job with `generateName: fetcher-backfill-` and `START_DATE`/`END_DATE` placeholders.
- `run-backfill.sh DD-MM-YYYY DD-MM-YYYY` fills in the dates and runs `kubectl create`.
- It is kept outside `deploy/k8s/` so that `kubectl apply -f deploy/k8s/` does not start a backfill.
